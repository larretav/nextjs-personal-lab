# Convenciones del proyecto

## Git

- Nunca hacer push directo a `main`. Todo cambio va por PR.
- Cada feature, chore, fix, etc. se trabaja en su propia rama independiente (no mezclar cambios de distinto tipo en una misma rama).
- Nombres de rama siempre en inglés (ej. `feat/home-automation-catalog`, no `feat/catalogo-domotico`).
- No hacer commits, push ni abrir PRs hasta que el usuario lo indique explícitamente. Se puede editar y verificar código libremente sin llegar a ese paso.
- Mensajes de commit: `"Bug en card de [módulo] arreglado"` (reemplazar `[módulo]` según corresponda; adaptar el verbo/hecho al tipo de cambio, no solo bugs).
- Títulos de PR: `"Nueva pagina de Proyecto agregada"` como estilo — nombre corto de lo agregado, y el cuerpo del PR con un listado de lo desarrollado.
